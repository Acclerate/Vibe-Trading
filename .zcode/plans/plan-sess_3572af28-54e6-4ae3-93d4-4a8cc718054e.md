# 雪球大V动态名单维护模块 — 实现方案

## 背景与关键发现

目标:维护一个 50 人小池子的大V名单,每月用动态评分函数评估,严格进出(进出阈值分离),CLI 手动触发。

**调研中的关键发现**:pysnowball SDK 源码核查后,它**几乎不覆盖大V社交数据**(无 profile/timeline/follow/排行榜/用户组合列表),只有 token 机制 + 单组合详情可用。因此采用你确认的**混合策略**:复用 pysnowball 的 `set_token`/`get_token` 作 token 层,大V社交数据直接调 xueqiu.com 网页接口,封装在 `XueqiuDataSource` 里,评分层不感知数据来源。发现机制用**内置种子集 + 手动维护**(不抓关注列表)。

## 模块落位

新建独立业务模块 `agent/src/influencer/`(不放进 `factors/zoo/` —— 大V名单不是横截面 alpha 因子,实体类型不同)。完全复用项目既有约定:
- 持久化模板照搬 `scheduled_research/store.py`(JSON 原子写 + `CorruptStoreError` 隔离)
- 数据模型照搬 `scheduled_research/models.py`(dataclass + `to_dict`/`from_dict`)
- 路径走 `config.paths.get_runtime_root()` → `~/.vibe-trading/influencer/`
- 重试用 `backtest.loaders.base.retry_with_budget`
- 日志用 `logging.getLogger(__name__)`

## 数据模型 (`models.py`)

仿 `scheduled_research/models.py` 的 dataclass 风格:

```python
class PoolStatus(str, Enum):
    ACTIVE = "active"       # 池内
    PROBATION = "probation" # 观察期(本月新进,下月才可被移除)
    REMOVED = "removed"     # 已移除(保留历史)

@dataclass
class Influencer:
    uid: str                        # 雪球用户 ID
    screen_name: str                # 昵称
    added_at: int                   # 加入池子时间(epoch ms)
    status: PoolStatus = PoolStatus.ACTIVE
    raw_metrics: Dict[str, Any] = field(default_factory=dict)  # 最近一次抓取的原始指标
    score_history: List[Dict] = field(default_factory=list)    # [{date, score, breakdown}]
    # to_dict() / from_dict() —— 照搬 models.py 模式
```

## 数据层 (`datasource.py`) — 混合策略

```python
class XueqiuDataSource:
    """混合 token 层:pysnowball.set_token + 直接调 xueqiu.com 接口。
    
    token 从 .env 的 XUEQIU_TOKEN 读取(或 pysnowball.set_token 注入)。
    所有 HTTP 经 retry_with_budget 重试 + 限速。
    """
    def fetch_profile(self, uid) -> dict          # /user/show.json → 粉丝/关注/简介
    def fetch_timeline(self, uid, page=1) -> dict # /v4/statuses/user_timeline.json → 帖子互动
    def fetch_user_cubes(self, uid) -> list       # /cubes/owner.json → 组合 ID 列表
    def fetch_cube_detail(self, cube_id) -> dict  # pysnowball.cube.detail() → 年化/回撤/夏普
    def fetch_all(self, uid) -> InfluencerMetrics # 聚合上述,返回评分所需结构化指标
```

**关键设计**:
- token 层复用 `pysnowball.set_token` / `os.environ['XUEQIUTOKEN']`(pysnowball 的约定)
- 接口失败时**降级不中断**:某个维度抓不到(如 timeline 被反爬),该维度记为 NaN,评分函数对 NaN 维度降权而不是整体失败
- 抓取结果带时间戳,供 `score_history` 追踪趋势

## 评分函数 (`scoring.py`)

实现上一轮回答中的 `score_bigv()`,五维加权:

```python
DEFAULT_WEIGHTS = {
    "influence": 0.20,    # log10(粉丝数),对数压缩防粉丝统治
    "engagement": 0.20,   # 互动率 = avg_likes / (followers * 0.1)
    "originality": 0.15,  # 原创率 + 长文占比
    "performance": 0.35,  # 组合:年化 + 夏普 + 卡尔马(最重要)
    "activity": 0.10,     # 近 30 天发帖频率
}

@dataclass
class ScoreBreakdown:
    total: float                    # 加权总分 [0,1]
    components: Dict[str, float]    # 各维度分项
    weights_used: Dict[str, float]
    missing_dims: List[str]         # 因抓取失败而缺失的维度(透明可观测)

def score_bigv(metrics, weights=None) -> ScoreBreakdown
```

**归一化策略**:每个维度内部做 0-1 归一化(用 sigmoid 或分位数),避免某维度量纲压制其他。performance 维度对 NaN 做惩罚(无组合的大V performance=0,而非忽略)。

## 月度刷新流程 (`refresh.py`)

```
CLI: python -m src.influencer.refresh [--dry-run] [--add UID] [--remove UID]

refresh_pool() 主流程:
1. load store → 当前池子
2. 对每个 ACTIVE + PROBATION 成员 fetch_all() 抓最新指标
3. 对每个种子集候选(不在池内的)也 fetch_all()
4. 全部 score_bigv() 评分
5. 严格进出决策(阈值分离,防抖动):
   - 进入:候选 score > ENTRY_THRESHOLD(如 0.55)且池子未满 → 加入,标记 PROBATION
   - 退出:池内成员 score < EXIT_THRESHOLD(如 0.35)且非 PROBATION → 移除
   - PROBATION 成员满 1 个月后转 ACTIVE(给观察期)
6. 保存快照 PoolSnapshot{date, decisions[], pool_size, added[], removed[]}
7. 原子写回 store
```

**阈值默认值**:池上限 50,ENTRY=0.55,EXIT=0.35,PROBATION 期 1 个月 —— 全部做成 `refresh.DEFAULTS` 常量,CLI 可覆盖。
